$Linux CheatSheet

Die wichtigsten Befehle für die Shell: Navigation, Dateien, Text, Rechte, Prozesse, Netzwerk, Pakete und Shell-Skripte. Code-Blöcke lassen sich per Klick kopieren.

    Navigation

    Wo bin ich, was liegt hier?

    Die Shell arbeitet immer in einem aktuellen Verzeichnis. Mit diesen Befehlen sehen Sie es und wechseln dorthin, wo Sie arbeiten wollen.

    pwd                  # aktuelles Verzeichnis anzeigen
ls                   # Inhalt auflisten
ls -la               # Details inkl. versteckter Dateien (.name)
ls -lh               # Größen lesbar (KB, MB)
cd /var/log          # absoluter Pfad
cd ..                # eine Ebene hoch
cd ~                 # Home-Verzeichnis (auch nur: cd)
cd -                 # zurück zum letzten Verzeichnis

    Hilfe finden

    Fast jeder Befehl dokumentiert sich selbst. man öffnet die Handbuchseite, --help gibt eine Kurzfassung aus.

    man ls               # Handbuch (q beendet, / sucht)
ls --help            # Kurzhilfe
man -k kopieren      # Handbücher nach Stichwort durchsuchen
type cd              # Art des Befehls (builtin, alias, Datei)
which python3        # Pfad des Programms
history              # Befehlsverlauf
!!                   # letzten Befehl wiederholen
sudo !!              # ... diesmal mit sudo

    PfadInhalt

    /home/namePersönliche Dateien der Benutzer (~)
    /rootHome-Verzeichnis des Administrators
    /etcKonfigurationsdateien

    Dateien & Verzeichnisse

    Anlegen, kopieren, verschieben, löschen

    Verschieben und Umbenennen ist derselbe Befehl (mv). Gelöscht wird endgültig, es gibt keinen Papierkorb.

    mkdir projekt            # Verzeichnis anlegen
mkdir -p a/b/c           # inkl. fehlender Elternverzeichnisse
touch datei.txt          # leere Datei anlegen / Zeitstempel setzen

cp a.txt b.txt           # Datei kopieren
cp -r ordner/ kopie/     # Verzeichnis rekursiv kopieren
mv alt.txt neu.txt       # umbenennen
mv datei.txt ~/Dokumente/  # verschieben

rm datei.txt             # Datei löschen
rm -r ordner/            # Verzeichnis löschen
rmdir leer/              # nur leeres Verzeichnis löschen

    Vorsicht: rm -rf fragt nicht nach und löscht alles darunter. Pfad vorher mit ls prüfen, vor allem mit sudo.

    Dateien ansehen

    Für kurze Dateien reicht cat, für lange nimmt man less. Mit tail -f verfolgen Sie Logdateien live.

    cat datei.txt            # ganze Datei ausgeben
less datei.txt           # blättern (q beenden, / suchen)
head -n 20 datei.txt     # erste 20 Zeilen
tail -n 20 datei.txt     # letzte 20 Zeilen
tail -f /var/log/syslog  # neue Zeilen live mitlesen
wc -l datei.txt          # Zeilen zählen
file bild.png            # Dateityp erkennen

    Links & Datei-Infos

    Ein symbolischer Link ist eine Verknüpfung auf eine andere Datei oder einen Ordner.

    ln -s /pfad/ziel linkname   # symbolischer Link
ls -l                       # Links erscheinen als  name -> ziel
stat datei.txt              # Größe, Rechte, Zeitstempel
du -sh ordner/              # Größe eines Ordners
tree -L 2                   # Verzeichnisbaum (2 Ebenen)

    Dateien suchen

    find durchsucht das Dateisystem live nach Name, Typ, Größe oder Alter. locate nutzt eine Datenbank und ist schneller.

    find . -name "*.log"            # nach Name
find . -iname "*.jpg"           # Groß-/Kleinschreibung egal
find /var -type d -name cache   # nur Verzeichnisse (-type f: Dateien)
find . -size +100M              # größer als 100 MB
find . -mtime -7                # in den letzten 7 Tagen geändert
find . -name "*.tmp" -delete    # gefundene Dateien löschen
find . -name "*.sh" -exec chmod +x {} \;

locate datei.txt                # (vorher: sudo updatedb)

    Text & Pipes

    grep: Text suchen

    grep filtert Zeilen, die ein Muster enthalten. Es ist das Werkzeug, das Sie am häufigsten brauchen werden.

    grep "fehler" datei.log        # Zeilen mit "fehler"
grep -i "fehler" datei.log     # Groß-/Kleinschreibung egal
grep -n "fehler" datei.log     # mit Zeilennummern
grep -v "debug" datei.log      # Zeilen OHNE "debug"
grep -c "fehler" datei.log     # Treffer zählen
grep -r "TODO" src/            # rekursiv in Ordner
grep -E "err|warn" datei.log   # erweiterter Regex (oder)
grep -C 2 "fehler" datei.log   # 2 Zeilen Kontext

    Pipes & Umleitung

    Die Pipe | reicht die Ausgabe eines Befehls als Eingabe an den nächsten weiter. Mit > landet die Ausgabe stattdessen in einer Datei.

    ZeichenBedeutung
    cmd > dateiAusgabe in Datei schreiben (überschreibt)
    cmd >> dateiAusgabe anhängen
    cmd < dateiDatei als Eingabe verwenden
    cmd 2> fehler.txtnur Fehlermeldungen umleiten
    cmd &> alles.txtAusgabe und Fehler in eine Datei
    cmd 2>/dev/nullFehlermeldungen verwerfen
    a | bAusgabe von a wird Eingabe von b
    a && bb nur, wenn a erfolgreich war
    a || bb nur, wenn a fehlgeschlagen ist
    a ; bnacheinander, unabhängig vom Ergebnis
    ls -l | grep ".txt" | wc -l        # .txt-Dateien zählen
cmd | tee ausgabe.txt              # anzeigen UND speichern
find . -name "*.log" | xargs rm    # Treffer als Argumente weitergeben

    Text bearbeiten

    Kleine Werkzeuge, die sich per Pipe kombinieren lassen: Spalten ausschneiden, sortieren, Duplikate zählen, ersetzen.

    sort datei.txt              # alphabetisch sortieren
sort -n zahlen.txt          # numerisch
sort -r datei.txt           # umgekehrt
sort datei.txt | uniq       # Duplikate entfernen
sort datei.txt | uniq -c    # Duplikate zählen
cut -d',' -f1,3 daten.csv   # Spalten 1 und 3 (Trenner Komma)
tr 'a-z' 'A-Z' < datei.txt   # in Großbuchstaben umwandeln
diff alt.txt neu.txt        # Unterschiede anzeigen

    sed & awk

    sed ersetzt Text Zeile für Zeile, awk verarbeitet Spalten (Felder). Beide sind kleine Programmiersprachen, hier nur die häufigsten Fälle.

    sed 's/alt/neu/' datei.txt        # erstes "alt" pro Zeile ersetzen
sed 's/alt/neu/g' datei.txt       # alle ersetzen
sed -i 's/alt/neu/g' datei.txt    # direkt in der Datei ändern
sed -n '5,10p' datei.txt          # Zeilen 5 bis 10 ausgeben
sed '/^#/d' datei.txt             # Kommentarzeilen entfernen

awk '{print $1}' datei.txt        # erste Spalte
awk -F: '{print $1, $3}' /etc/passwd   # Trenner ":" , Spalte 1 und 3
awk '$3 > 100' daten.txt          # Zeilen mit Spalte 3 > 100
awk '{s+=$1} END {print s}' zahlen.txt  # Summe der ersten Spalte

    Archive & Kompression

    Mit tar packt man viele Dateien in ein Archiv, mit gzip (Option z) wird es zusätzlich komprimiert.

    tar -czvf backup.tar.gz ordner/   # packen + komprimieren
tar -xzvf backup.tar.gz           # entpacken
tar -xzvf backup.tar.gz -C /ziel  # in anderes Verzeichnis entpacken
tar -tzvf backup.tar.gz           # Inhalt anzeigen

zip -r archiv.zip ordner/
unzip archiv.zip
gzip datei.txt                    # -> datei.txt.gz
gunzip datei.txt.gz

    Merkhilfe: create, extract, z = gzip, verbose, file.

    Rechte & Benutzer

    Dateirechte lesen

    Jede Datei hat Rechte für den Besitzer (u), die Gruppe (g) und alle anderen (o). Pro Gruppe gibt es lesen (r), schreiben (w) und ausführen (x).

    -rwxr-xr--  1 anna dev  4096 Mar  3 10:00 skript.sh
│└┬┘└┬┘└┬┘     │    │
│ │  │  └ andere: nur lesen (r--)
│ │  └ Gruppe: lesen + ausführen (r-x)
│ └ Besitzer: alles (rwx)
└ Typ: - Datei, d Verzeichnis, l Link
    ZahlRechtZahlRecht
    4r (lesen)6rw-
    2w (schreiben)5r-x
    1x (ausführen)7rwx

    chmod & chown

    chmod ändert die Rechte, chown den Besitzer. Zahlen: eine Ziffer pro Gruppe (Besitzer, Gruppe, andere).

    chmod 755 skript.sh        # rwxr-xr-x  (Programme, Ordner)
chmod 644 datei.txt        # rw-r--r--  (normale Dateien)
chmod 600 id_rsa           # rw-------  (nur Besitzer, z. B. SSH-Schlüssel)
chmod +x skript.sh         # ausführbar machen
chmod u+w,g-w datei.txt    # Besitzer +schreiben, Gruppe -schreiben
chmod -R 755 ordner/       # rekursiv

chown anna datei.txt       # Besitzer ändern
chown anna:dev datei.txt   # Besitzer und Gruppe
sudo chown -R www-data: /var/www

    chmod 777 erlaubt jedem alles. Vermeiden, es löst selten ein Problem sauber.

    sudo & Benutzer

    sudo führt einen einzelnen Befehl mit Administratorrechten aus. Dauerhaft als root zu arbeiten ist nicht empfehlenswert.

    whoami                     # aktueller Benutzer
id                         # UID, GID, Gruppen
sudo befehl                # als root ausführen
sudo -i                    # Root-Shell (mit exit verlassen)
su - anna                  # zu anderem Benutzer wechseln

sudo useradd -m -s /bin/bash neu   # Benutzer mit Home anlegen
sudo passwd neu                    # Passwort setzen
sudo usermod -aG sudo neu          # zur Gruppe sudo hinzufügen
sudo userdel -r neu                # Benutzer samt Home löschen
groups anna                        # Gruppen anzeigen

    Prozesse & Dienste

    Prozesse ansehen & beenden

    Jedes laufende Programm ist ein Prozess mit einer Nummer (PID). Mit der PID kann man ihn beenden.

    ps aux                     # alle Prozesse
ps aux | grep nginx        # bestimmten Prozess suchen
top                        # Live-Übersicht (q beendet)
htop                       # komfortablere Variante
pgrep nginx                # PID nach Name

kill 1234                  # Prozess höflich beenden (SIGTERM)
kill -9 1234               # hart beenden (SIGKILL), nur im Notfall
pkill nginx                # nach Name beenden
killall firefox

    Hintergrund & Jobs

    Ein & am Ende startet einen Befehl im Hintergrund, die Shell bleibt benutzbar.

    langerbefehl &            # im Hintergrund starten
jobs                      # laufende Jobs der Shell
fg %1                     # Job 1 in den Vordergrund
bg %1                     # angehaltenen Job im Hintergrund fortsetzen
nohup befehl &            # läuft weiter, auch nach dem Abmelden
nice -n 10 befehl         # mit niedrigerer Priorität starten

    systemd: Dienste steuern

    Fast alle modernen Distributionen verwalten Hintergrunddienste mit systemctl. enable startet einen Dienst beim Booten, start sofort.

    systemctl status nginx          # Zustand und letzte Logzeilen
sudo systemctl start nginx
sudo systemctl stop nginx
sudo systemctl restart nginx    # stoppen + starten
sudo systemctl reload nginx     # Konfiguration neu laden, ohne Neustart
sudo systemctl enable nginx     # beim Booten starten
sudo systemctl enable --now nginx   # aktivieren und sofort starten
sudo systemctl disable nginx
systemctl list-units --type=service --state=running
systemctl --failed              # fehlgeschlagene Dienste

    Logs mit journalctl

    Das systemd-Journal sammelt die Logs aller Dienste an einer Stelle.

    journalctl -u nginx             # Logs eines Dienstes
journalctl -u nginx -f          # live mitlesen
journalctl -b                   # seit dem letzten Boot
journalctl -p err               # nur Fehler und schlimmer
journalctl --since "1 hour ago"
journalctl --disk-usage

    Eigener Dienst (Unit-Datei)

    Legen Sie die Datei unter /etc/systemd/system/meindienst.service an und laden Sie systemd danach neu.

    [Unit]
Description=Mein Dienst
After=network.target

[Service]
ExecStart=/usr/local/bin/meindienst
Restart=on-failure
User=dienst

[Install]
WantedBy=multi-user.target
    sudo systemctl daemon-reload
sudo systemctl enable --now meindienst

    Laufwerke einhängen

    Ein Datenträger muss in den Verzeichnisbaum eingehängt werden (mount), bevor man auf ihn zugreift. Dauerhaft geschieht das über /etc/fstab.

    sudo mount /dev/sdb1 /mnt     # einhängen
sudo umount /mnt              # aushängen
mount | grep sdb              # was ist eingehängt?
lsblk -f                      # Dateisysteme und UUIDs
    # /etc/fstab
# Gerät                     Ziel   Typ   Optionen   dump pass
UUID=1234-ABCD              /data  ext4  defaults   0    2

    Ein Fehler in der fstab kann das Booten verhindern. Vor dem Neustart mit sudo mount -a testen.

    Firewall (ufw)

    Unter Ubuntu und Debian ist ufw eine einfache Oberfläche für die Firewall. Erlauben Sie SSH, bevor Sie sie aktivieren.

    sudo ufw allow 22/tcp          # SSH erlauben
sudo ufw allow 80,443/tcp      # Web erlauben
sudo ufw enable
sudo ufw status verbose
sudo ufw delete allow 80/tcp

    Wer per SSH verbunden ist und Port 22 nicht freigibt, sperrt sich beim Aktivieren selbst aus.

    Shell-Skripte Bash

    Erstes Skript

    Ein Skript ist eine Textdatei mit Befehlen. Die erste Zeile (Shebang) legt fest, welches Programm sie ausführt. Danach muss die Datei ausführbar sein.

    #!/usr/bin/env bash
set -euo pipefail    # bei Fehler abbrechen, undefinierte Variablen verbieten

echo "Hallo $USER"
    chmod +x hallo.sh
./hallo.sh              # ausführen
bash hallo.sh           # alternativ, ohne x-Recht

    Variablen & Argumente

    Bei Zuweisungen steht kein Leerzeichen um das =. Variablen immer in Anführungszeichen verwenden, sonst brechen Leerzeichen im Wert den Befehl auf.

    name="Anna"
echo "Hallo $name"
echo "Pfad: ${name}_alt"            # Klammern, wenn Text folgt
heute=$(date +%F)                   # Ausgabe eines Befehls speichern
read -p "Dein Name: " eingabe       # Eingabe lesen

# Argumente beim Aufruf:  ./skript.sh eins zwei
echo "$0"       # Skriptname
echo "$1 $2"    # erstes und zweites Argument
echo "$#"       # Anzahl der Argumente
echo "$@"       # alle Argumente
echo "$?"       # Exit-Code des letzten Befehls

    Bedingungen

    Ein Befehl gilt als erfolgreich, wenn sein Exit-Code 0 ist. [[ ]] prüft Bedingungen, vor und nach den Klammern gehört ein Leerzeichen.

    if [[ -f "$datei" ]]; then
    echo "Datei existiert"
elif [[ -d "$datei" ]]; then
    echo "Ist ein Verzeichnis"
else
    echo "Nicht gefunden"
fi

[[ $n -gt 5 ]] && echo "größer als 5"

case "$1" in
    start)  echo "starte" ;;
    stop)   echo "stoppe" ;;
    *)      echo "Aufruf: $0 start|stop" ;;
esac

    Funktionen & Arrays

    Funktionen bündeln wiederkehrende Schritte. Ihre Argumente heißen wie beim Skript $1, $2, ...

    local name="$1"

    Exit-Codes & Aufräumen

    Skripte melden Erfolg oder Fehler über ihren Exit-Code. Mit trap räumen Sie auch bei Abbruch auf.

    exit 0                   # Erfolg
exit 1                   # Fehler

if ! grep -q "x" datei; then
    echo "nicht gefunden" >&2     # Meldung auf stderr
    exit 1
fi

tmp=$(mktemp)
trap 'rm -f "$tmp"' EXIT         # beim Beenden ausführen

    Best Practices

    Sicher arbeiten

    • Vor rm -r den Pfad mit ls prüfen, nie blind rm -rf mit Variablen (rm -rf "$x/" wird bei leerem $x zu /)
    • Nur einzelne Befehle mit sudo ausführen, nicht dauerhaft als root arbeiten
    • Befehle aus dem Internet nicht blind einfügen, vor allem nicht curl ... | sudo bash
    • Vor größeren Änderungen eine Kopie der Konfiguration anlegen: sudo cp datei datei.bak
    • SSH mit Schlüsseln statt Passwörtern, Schlüsseldatei mit chmod 600

    Effizient arbeiten

    • Tab und Strg+R konsequent nutzen
    • Kleine Befehle per Pipe kombinieren statt große Programme zu schreiben
    • Dateinamen ohne Leerzeichen wählen, sonst Pfade in Anführungszeichen setzen
    • Skripte mit set -euo pipefail beginnen und Variablen in Anführungszeichen setzen
    • Bei Unklarheit: man befehl oder befehl --help lesen
    • Wiederkehrendes als alias oder Skript ablegen

    Übungen mit Lösung

    Vorbereitung

    Alle Übungen laufen in einem eigenen Übungsordner. So kann nichts Wichtiges kaputtgehen. Wenn Ihr Kurs oder Ihre Aufgabe einen anderen Ordner vorgibt, nehmen Sie diesen Pfad statt ~/uebung.

    mkdir -p ~/uebung                 # Übungsordner anlegen (falls nicht vorhanden)
cd ~/uebung                       # hineinwechseln
echo "Hallo Welt" > hello.txt     # Beispieldatei für Übung 2
pwd                               # Kontrolle: /home/<name>/uebung
ls

    Aufräumen am Ende: cd ~ && rm -r ~/uebung löscht den ganzen Übungsordner. Vorher mit pwd prüfen, dass Sie nicht im falschen Verzeichnis sind.

    Übung 1 · Verzeichnis anlegen und auflisten

    Aufgabe: Lege im Übungsordner ~/uebung das Verzeichnis notes an und speichere die Ausgabe von ls -d notes in der Datei notes/listing.txt.

    Geübt wird: Verzeichnis anlegen, relative Pfade, die Option -d und die Umleitung der Ausgabe in eine Datei. Versuchen Sie es zuerst selbst, die Lösung ist eingeklappt.

    Lösung anzeigen 
    cd ~/uebung       # in den Übungsordner wechseln
mkdir notes                       # Verzeichnis "notes" anlegen
ls -d notes > notes/listing.txt   # Ausgabe von ls -d in die Datei schreiben
cat notes/listing.txt             # Kontrolle: zeigt  notes

    Was jeder Befehl macht

    BefehlWirkung
    cd ~/uebungchange directory: Die Shell wechselt in dieses Verzeichnis. ~ steht für Ihr Home-Verzeichnis.
    mkdir notesmake directory: legt einen neuen, leeren Ordner notes im aktuellen Verzeichnis an.
    lslist: zeigt den Inhalt eines Verzeichnisses.
    ls -d notesOption -d (directory): zeigt den Eintrag selbst statt seines Inhalts. Die Ausgabe ist einfach der Name notes.
    >Umleitung: Statt auf den Bildschirm geht die Ausgabe in eine Datei. Die Datei wird angelegt oder, falls vorhanden, überschrieben.
    cat notes/listing.txtGibt den Dateiinhalt aus. Damit prüfen Sie, ob wirklich notes darin steht.

    Warum macht man es so?

    Reihenfolge: mkdir muss zuerst kommen. Die Umleitung > legt zwar die Datei an, aber nie fehlende Verzeichnisse. Ohne notes bricht die Shell mit No such file or directory ab.

    Warum -d? Ohne die Option würde ls notes den Inhalt des Ordners zeigen, und der ist leer. Mit -d erhalten Sie den Namen des Ordners selbst. So prüft man zum Beispiel, ob ein Verzeichnis existiert, oder listet mit ls -d */ nur die Unterverzeichnisse.

    Warum umleiten? Ein Befehl schreibt normalerweise in das Terminal (Standardausgabe). Mit > können Sie das Ergebnis speichern, weiterverarbeiten oder, wie hier, später von einem Skript oder einer Lehrkraft prüfen lassen. Damit das klappt, muss die Datei genau am verlangten Pfad liegen.

    Relative Pfade: notes/listing.txt gilt vom aktuellen Verzeichnis aus. Deshalb zuerst cd und im Zweifel pwd zur Kontrolle.

    Typische Fehler

    FehlerFolge
    mkdir vergessenbash: notes/listing.txt: No such file or directory
    ls notes ohne -dDie Shell legt listing.txt an, bevor ls läuft. ls findet dann genau diese Datei, und in der Datei steht listing.txt statt notes.
    >> statt >Die Ausgabe wird angehängt. Bei jedem erneuten Ausführen kommt eine Zeile dazu.
    falsches VerzeichnisDie Datei landet woanders. Mit pwd prüfen, in welchem Ordner Sie sind.

    Übung 1 · Zum Weiterüben

    Variationen der gleichen Technik. Probieren Sie sie im Übungsordner aus und schauen Sie mit cat nach, was in der Datei steht.

    Lösung a) 
    ls -d */ > notes/ordner.txt     # Muster */ trifft nur Verzeichnisse

    Die Shell ersetzt */ durch alle Namen, die auf einen Schrägstrich enden, also nur durch Verzeichnisse. -d sorgt dafür, dass ls deren Namen ausgibt statt ihren Inhalt.

    Lösung b)

    echo gibt Text aus, >> hängt ihn ans Dateiende an, ohne den bisherigen Inhalt zu löschen.

    Lösung c) 
    ls -d gibtesnicht 2> notes/fehler.txt
cat notes/fehler.txt

    Fehlermeldungen laufen über einen eigenen Kanal (Standardfehler, Nummer 2). 2> leitet nur diesen Kanal um, normale Ausgabe bliebe im Terminal.

    d) Lege projekt/src/tests in einem Schritt an und zähle danach die Einträge in projekt.

    Lösung d)

    Übung 2 · Datei kopieren und lesen

    Aufgabe: Kopiere in ~/uebung die Datei hello.txt nach notes/hello-copy.txt, ohne das Original zu entfernen. Lies die Kopie mit cat und speichere die Ausgabe in notes/copy-check.txt.

    Geübt wird: Kopieren mit cp, der Unterschied zu mv, Quelle und Ziel angeben, Dateien mit cat lesen und die Ausgabe wieder mit > speichern. Der Ordner notes stammt aus Übung 1.

    Lösung anzeigen 
    cd ~/uebung
cp hello.txt notes/hello-copy.txt           # kopieren, Original bleibt
cat notes/hello-copy.txt > notes/copy-check.txt   # Kopie lesen, Ausgabe speichern

ls hello.txt notes/                         # Kontrolle: Original und Kopien da
diff hello.txt notes/copy-check.txt         # keine Ausgabe = Inhalt identisch

    Was jeder Befehl macht

    BefehlWirkung
    cp hello.txt notes/hello-copy.txtcopy: Der erste Pfad ist die Quelle, der zweite das Ziel. Es entsteht eine neue Datei mit demselben Inhalt, die Quelle bleibt unverändert.
    cat notes/hello-copy.txtGibt den Inhalt der Kopie im Terminal aus (von concatenate, „aneinanderhängen“).
    > notes/copy-check.txtLeitet diese Ausgabe in die Datei copy-check.txt um, statt sie anzuzeigen.
    ls hello.txt notes/Zeigt, dass das Original noch da ist und notes beide neuen Dateien enthält.
    diff a bVergleicht zwei Dateien. Keine Ausgabe heißt: identisch.

    Warum macht man es so?

    cp statt mv: mv verschiebt, danach gäbe es hello.txt nicht mehr. Die Aufgabe verlangt ausdrücklich, das Original zu behalten, also kopiert man.

    Ziel mit Dateiname: Mit notes/hello-copy.txt bestimmen Sie den neuen Namen. Schreiben Sie nur notes/, behält die Kopie den alten Namen hello.txt.

    Zwei Schritte: Erst kopieren, dann die Kopie lesen. So sehen Sie, dass das Kopieren funktioniert hat, denn cat meldet einen Fehler, wenn die Datei fehlt. Das Ergebnis in copy-check.txt belegt es auch für jede spätere Kontrolle.

    Ausgabe statt Bildschirm: cat schreibt wie ls in die Standardausgabe. Mit > wird daraus eine Datei, genau wie in Übung 1.

    Typische Fehler

    FehlerFolge
    mv statt cpDas Original ist weg, die Aufgabe ist nicht erfüllt.
    cp hello.txt notesDie Kopie heißt notes/hello.txt, nicht hello-copy.txt.
    Ordner notes fehltcp: cannot create regular file 'notes/…': No such file or directory. Erst mkdir notes.
    Falsches Verzeichnis oder Tippfehlercp: cannot stat 'hello.txt': No such file or directory. Mit pwd und ls prüfen.
    Zieldatei existiert schoncp überschreibt sie ohne Nachfrage. Mit cp -i fragt es vorher.

    Übung 2 · Zum Weiterüben

    Probieren Sie diese Varianten im Übungsordner aus und prüfen Sie jeweils mit ls und cat.

    a) Kopiere hello.txt in den Ordner notes, ohne den Namen zu ändern.

    Lösung a) 
    cp hello.txt notes/
ls notes/

    Endet das Ziel auf einen Ordner, übernimmt cp den Dateinamen der Quelle. Der Schrägstrich am Ende macht deutlich, dass notes ein Ordner sein soll.

    b) Kopiere alle .txt-Dateien des aktuellen Ordners nach notes.

    Lösung b) 
    cp *.txt notes/

    Die Shell ersetzt *.txt durch alle passenden Dateinamen, cp bekommt also mehrere Quellen und als letztes Argument den Zielordner.

    Lösung c) 
    cp -i hello.txt notes/hello-copy.txt

    -i steht für interactive. Mit y bestätigen Sie, mit n bleibt die Zieldatei unverändert.

    Übung 3 · Dateirechte setzen

    Aufgabe: Setze in ~/uebung die Rechte von notes/greeting.txt auf rw-r----- (Modus 640).

    Geübt wird: Rechte als Zahl angeben, mit chmod ändern und mit ls -l kontrollieren. Die Datei greeting.txt muss existieren. Falls nicht, legen Sie sie vorher an (siehe Lösung).

    Lösung anzeigen 
    cd ~/uebung
echo "Hallo" > notes/greeting.txt          # nur nötig, falls die Datei fehlt

ls -l notes/greeting.txt                   # vorher:  -rw-r--r--  (644)
chmod 640 notes/greeting.txt               # Rechte setzen
ls -l notes/greeting.txt                   # nachher: -rw-r-----  (640)
stat -c '%a %A' notes/greeting.txt         # Kontrolle: 640 -rw-r-----

    Rechte als Zahl berechnen

    Jede der drei Ziffern gehört zu einer Gruppe: Besitzer, Gruppe, andere. Jede Ziffer ist die Summe aus lesen = 4, schreiben = 2, ausführen = 1.

    Besitzer (u)Gruppe (g)Andere (o)
    Textrw-r-----
    Rechnung4 + 2 + 04 + 0 + 00 + 0 + 0
    Ziffer640

    Ergebnis: 640. Der Besitzer darf lesen und schreiben, die Gruppe nur lesen, alle anderen gar nichts.

    Was jeder Befehl macht

    BefehlWirkung
    chmod 640 dateichange mode: setzt die Rechte der Datei auf genau diesen Wert. Alles, was vorher galt, wird ersetzt.
    ls -l dateiLanges Format. Die erste Spalte zeigt Typ und Rechte, danach Besitzer, Gruppe, Größe, Datum und Name.
    stat -c '%a %A' dateiGibt die Rechte in beiden Schreibweisen aus: als Zahl (640) und als Text (-rw-r-----).
    -rw-r-----  1 anna dev  6 Okt  4 10:00 greeting.txt
│└┬┘└┬┘└┬┘
│ │  │  └ andere:   ---  (keine Rechte)
│ │  └ Gruppe:      r--  (lesen)
│ └ Besitzer:       rw-  (lesen + schreiben)
└ Typ: - Datei, d Verzeichnis

    Warum macht man es so?

    Rechte schützen Dateien: Linux ist ein Mehrbenutzersystem. Mit 640 kann nur der Besitzer die Datei ändern, die Gruppe darf sie lesen und alle anderen Benutzer sehen den Inhalt nicht.

    Zahl statt Text: Die Zahlenschreibweise legt alle neun Rechte in einem Schritt fest und ist kurz. Alternativ geht auch der symbolische Weg, der gleichwertig ist: chmod u=rw,g=r,o= notes/greeting.txt. Dabei bedeutet o=, dass für „andere“ nichts gesetzt wird.

    Kontrolle nach der Änderung: chmod gibt bei Erfolg nichts aus. Erst ls -l zeigt, ob wirklich -rw-r----- herauskam.

    Typische Fehler

    FehlerFolge
    chmod 460 statt 640Ziffern vertauscht: Der Besitzer bekäme nur lesen, die Gruppe lesen und schreiben (r--rw----).
    Falscher Pfad oder falsches Verzeichnischmod: cannot access 'greeting.txt': No such file or directory. Mit pwd und ls notes prüfen.
    chmod +w oder chmod +xDas fügt Rechte hinzu, setzt aber nicht den gewünschten Zielwert. Für einen exakten Wert Zahl oder u=…,g=…,o=… nehmen.
    chmod 777Gibt allen alle Rechte. Das ist fast nie nötig und unsicher.
    Rechte mit Besitzer verwechselnchmod ändert nur die Rechte. Den Besitzer ändert man mit chown.

    Übung 3 · Zum Weiterüben

    Prüfen Sie nach jedem Schritt mit ls -l oder stat -c '%a %A' datei.

    a) Setze notes/greeting.txt so, dass nur der Besitzer lesen und schreiben darf (rw-------).

    Lösung a) 
    chmod 600 notes/greeting.txt

    6 für den Besitzer (lesen + schreiben), 0 für Gruppe und andere. Das ist die übliche Einstellung für private Dateien wie SSH-Schlüssel.

    b) Lege ein Skript skript.sh an und mache es für alle ausführbar.

    Lösung b) 
    touch skript.sh
chmod +x skript.sh
ls -l skript.sh

    +x fügt das Ausführungsrecht für Besitzer, Gruppe und andere hinzu, ohne die übrigen Rechte zu verändern. Das ist der Normalfall bei Skripten.

    c) Setze skript.sh auf rwxr-x---, einmal als Zahl und einmal symbolisch.

    Lösung c) 
    chmod 750 skript.sh
chmod u=rwx,g=rx,o= skript.sh     # gleichwertig

    Besitzer 4+2+1 = 7, Gruppe 4+0+1 = 5, andere 0.

    d) Rechne selbst: Welche Zahl gehört zu rw-r--r-- und welche zu rwxr-xr-x?

    Lösung d)

    rw-r--r-- = 6 4 4 = 644 (normale Datei). rwxr-xr-x = 7 5 5 = 755 (Programm oder Ordner).

    e) Erzeuge eine neue leere Datei und schau nach, welche Rechte sie von selbst bekommt.

    Lösung e) 
    touch neu.txt
ls -l neu.txt          # meist -rw-r--r--  (644)
umask                  # zeigt die Maske, meist 0022

    Neue Dateien starten mit 666 minus der umask. Bei 0022 ergibt das 644. Neue Verzeichnisse starten mit 777 minus umask, also 755.

    Übung 4 · Weiteres Verzeichnis anlegen

    Aufgabe: Lege das Verzeichnis ~/uebung/projects an.

    Geübt wird: mkdir mit einem vollständigen (absoluten) Pfad und der Unterschied zwischen absoluten und relativen Pfaden.

    Lösung anzeigen 
    mkdir ~/uebung/projects          # mit vollem Pfad, funktioniert von überall

# gleichwertig, wenn Sie schon in ~/uebung sind:
cd ~/uebung
mkdir projects

ls -d ~/uebung/projects          # Kontrolle: gibt den Pfad aus
ls -ld ~/uebung/projects         # zeigt drwxr-xr-x ... (d = Verzeichnis)

    Absolute und relative Pfade

    Die Aufgabe nennt den vollständigen Pfad. Es gibt zwei Schreibweisen, die zum gleichen Ort führen können.

    ArtBeispielBedeutung
    absolut/home/anna/uebung/projectsbeginnt bei /, gilt von überall
    mit Home~/uebung/projects~ ist Ihr Home-Verzeichnis, gilt ebenfalls von überall
    relativprojectsgilt vom aktuellen Verzeichnis aus
    relativ../projects.. = eine Ebene höher

    Was jeder Befehl macht

    BefehlWirkung
    mkdir ~/uebung/projectsmake directory: legt projects in ~/uebung an. ~/uebung muss schon existieren.
    ls -d pfadZeigt den Eintrag selbst, nicht seinen Inhalt. Bei Erfolg wird der Pfad ausgegeben, sonst eine Fehlermeldung.
    ls -ld pfadWie oben, im langen Format. Ein d am Anfang der Rechte zeigt: ein Verzeichnis.

    Warum macht man es so?

    Vollständiger Pfad: Er funktioniert unabhängig davon, in welchem Ordner Sie gerade sind. Das ist besonders in Skripten und bei Aufgaben mit einer genauen Pfadvorgabe sicher.

    Relativ ist kürzer: Wer schon in ~/uebung steht, schreibt nur mkdir projects. Der Fehler dabei: Ohne vorheriges pwd legen Sie den Ordner leicht im falschen Verzeichnis an.

    Kontrolle: mkdir meldet bei Erfolg nichts. Mit ls -d prüfen Sie, ob der Ordner wirklich da ist.

    Typische Fehler

    FehlerFolge
    Ordner existiert schonmkdir: cannot create directory 'projects': File exists. Mit mkdir -p bleibt die Meldung aus.
    Elternordner fehltmkdir: cannot create directory 'a/b': No such file or directory. Mit -p werden fehlende Ebenen mit angelegt.
    Leerzeichen im Namenmkdir mein projekt legt zwei Ordner an, mein und projekt. Besser mkdir "mein projekt" oder ganz ohne Leerzeichen.
    Groß-/KleinschreibungProjects und projects sind verschiedene Ordner. Die Aufgabe verlangt genau projects.
    Tippfehler im PfadDer Ordner liegt am falschen Ort, die Kontrolle mit ls -d schlägt fehl.

    Übung 4 · Zum Weiterüben

    Alle Befehle im Übungsordner ~/uebung ausführen und mit ls kontrollieren.

    a) Lege in projects die drei Ordner web, api und docs an.

    Lösung a) 
    mkdir projects/web projects/api projects/docs     # mehrere Argumente
mkdir projects/{web,api,docs}                     # kürzer mit Klammern
ls projects

    mkdir nimmt beliebig viele Namen. Die Schreibweise mit geschweiften Klammern wird von der Shell zu den drei Pfaden aufgelöst, bevor mkdir startet. Den zweiten Befehl brauchen Sie nur, wenn die Ordner noch nicht existieren.

    b) Lege archiv/2026/oktober in einem Schritt an.

    Lösung b) 
    mkdir -p archiv/2026/oktober
ls -R archiv

    -p (parents) legt fehlende Elternordner mit an. ls -R listet rekursiv alle Unterordner.

    c) Führe mkdir -p projects aus, obwohl projects schon existiert. Was passiert?

    Lösung c) 
    mkdir -p projects
echo $?          # 0 = Erfolg, kein Fehler

    Mit -p ist mkdir „idempotent“: Existiert der Ordner schon, passiert nichts und es gibt keinen Fehler. Das ist praktisch in Skripten, die mehrfach laufen.

    d) Lege einen Ordner mit dem Namen mein projekt (mit Leerzeichen) an und prüfe ihn.

    Lösung d) 
    mkdir "mein projekt"
ls -d "mein projekt"
ls -d mein\ projekt         # alternativ: Leerzeichen mit \ maskieren

    Anführungszeichen halten den Namen zusammen. Auch bei cd, cp und rm müssen solche Namen in Anführungszeichen stehen. Deshalb vermeidet man Leerzeichen am besten ganz, zum Beispiel mit mein-projekt.

    e) Prüfe per Befehl, ob projects ein Verzeichnis ist, und gib dann einen Satz aus.

    Lösung e) 
    test -d projects && echo "projects ist ein Verzeichnis"
[[ -d projects ]] && echo "projects ist ein Verzeichnis"   # gleichwertig in Bash

    -d ist hier ein Test, nicht die Option von ls. Der Befehl vor && liefert nur bei Erfolg den Exit-Code 0, dann läuft echo.

    Übung 5 · Verschachtelte Ordner anlegen

    Aufgabe: Lege ~/uebung/projects/linux/basics an.

    Geübt wird: mkdir -p legt eine ganze Ordnerkette in einem Schritt an. Der Ordner projects stammt aus Übung 4, er muss aber nicht existieren.

    Lösung anzeigen 
    mkdir -p ~/uebung/projects/linux/basics

find ~/uebung/projects -type d       # Kontrolle: alle Ordner darunter
ls -R ~/uebung/projects              # alternativ: rekursive Auflistung

    Erwartete Ausgabe von find: ~/uebung/projects, ~/uebung/projects/linux und ~/uebung/projects/linux/basics (jeweils mit ausgeschriebenem Home-Pfad).

    Was jeder Befehl macht

    BefehlWirkung
    mkdir -p pfad-p steht für parents (Elternordner). mkdir prüft jede Ebene des Pfads von links nach rechts und legt nur die an, die noch fehlen.
    find pfad -type dListet alle Einträge unterhalb von pfad, die Verzeichnisse sind (-type d), also die ganze Ordnerstruktur.
    ls -R pfadRekursiv: zeigt den Inhalt jedes Unterordners, jeweils unter dessen Namen.

    Warum macht man es so?

    Ohne -p geht es nur Schritt für Schritt: mkdir legt immer nur die letzte Ebene an und erwartet, dass alle davor schon existieren. Fehlt linux, bricht der Befehl ab.

    mkdir ~/uebung/projects/linux/basics
# mkdir: cannot create directory '…/projects/linux/basics': No such file or directory

# ohne -p wären zwei getrennte Befehle nötig:
mkdir ~/uebung/projects/linux
mkdir ~/uebung/projects/linux/basics

    Mit -p ein Befehl: Es spielt keine Rolle, wie viel vom Pfad schon existiert. Vorhandene Ebenen bleiben unverändert, es gibt keine Fehlermeldung, und das Ergebnis ist immer dasselbe. Deshalb setzt man -p auch in Skripten ein, die mehrfach laufen.

    Typische Fehler

    FehlerFolge
    -p vergessenmkdir: cannot create directory '…': No such file or directory, sobald eine Ebene fehlt.
    Tippfehler in einer Zwischenebene-p legt auch projekts brav an, ohne Warnung. Dann existiert ein zweiter, falscher Baum, und die Kontrolle mit find zeigt es.
    Eine Datei liegt im WegExistiert auf dem Pfad eine Datei gleichen Namens, meldet mkdir Not a directory.
    Leerzeichen im PfadJedes Wort wird als eigener Pfad verstanden. Pfade ohne Leerzeichen wählen oder in Anführungszeichen setzen.
    -p hinter dem PfadMeist egal, aber die Konvention ist: Optionen zuerst, dann der Pfad.

    Übung 8 · Mehrere Zeilen schreiben

    Aufgabe: Lege in ~/uebung die Datei notes/commands.txt an. Sie soll genau drei Zeilen enthalten: pwd, ls, mkdir, in dieser Reihenfolge.

    Geübt wird: printf mit Zeilenumbrüchen (\n), der Unterschied zu echo und die Kontrolle mit cat. Die Wörter sind hier nur Text. Es wird kein Befehl ausgeführt.

    Lösung anzeigen 
    cd ~/uebung
mkdir -p notes                              # nur nötig, falls notes fehlt
printf 'pwd\nls\nmkdir\n' > notes/commands.txt

cat notes/commands.txt                      # zeigt die drei Zeilen
wc -l notes/commands.txt                    # zählt: 3

    Was jeder Befehl macht

    BefehlWirkung
    printf 'pwd\nls\nmkdir\n'Gibt den Text aus und ersetzt dabei \n durch einen Zeilenumbruch. Anders als echo hängt printf keinen Umbruch von selbst an, daher das \n am Ende.
    > notes/commands.txtSchreibt diese Ausgabe in die Datei (überschreibt, falls vorhanden).
    cat dateiGibt den Dateiinhalt aus, zur Sichtkontrolle.
    wc -l dateiword count, Option -l: zählt die Zeilenumbrüche, also die Zeilen. Erwartet: 3.

    Warum macht man es so?

    Ein Befehl, mehrere Zeilen: Mit printf und \n steht der ganze Inhalt in einem Aufruf. Die Datei wird in einem Schritt geschrieben und enthält danach genau das, was Sie angegeben haben.

    Warum nicht echo? In Bash schreibt echo "pwd\nls" den Text wörtlich mit Backslash. Erst echo -e wertet \n aus, und das Verhalten unterscheidet sich je nach Shell. printf verhält sich überall gleich und ist deshalb die sichere Wahl.

    Das Zeilenende zählt: Eine Zeile gilt unter Linux erst dann als vollständig, wenn sie mit einem Zeilenumbruch endet. Fehlt er hinter mkdir, zählt wc -l nur 2 Zeilen. Darum steht ein \n am Ende.

    Text, kein Befehl: In den Anführungszeichen ist pwd nur ein Wort. Mit $(pwd) dagegen würde der Befehl ausgeführt und sein Ergebnis eingesetzt.

    Typische Fehler

    FehlerFolge
    echo "pwd\nls\nmkdir"Die Datei enthält eine Zeile mit den Zeichen pwd\nls\nmkdir.
    Kein \n am EndeDie letzte Zeile hat kein Zeilenende, wc -l meldet 2.
    Ein zusätzliches \n (\n\n)Es entsteht eine Leerzeile, die Datei hat vier Zeilen statt drei.
    Falsche Reihenfolge oder TippfehlerDie Datei stimmt nicht mit der Vorgabe überein. Mit cat prüfen.
    Einzelne echo-Befehle alle mit >Jeder Aufruf überschreibt die Datei, übrig bleibt nur die letzte Zeile. Ab der zweiten Zeile >> verwenden.
    Doppelte Anführungszeichen mit $ oder !Die Shell ersetzt solche Zeichen. Bei festem Text besser einfache Anführungszeichen '...'.

    Übung 9 · Text anhängen

    Aufgabe: Hänge in ~/uebung eine vierte Zeile grep an die Datei notes/commands.txt an.

    Geübt wird: >> hängt an, > überschreibt. Die Datei stammt aus Übung 8 (drei Zeilen: pwd, ls, mkdir). Falls sie fehlt, legen Sie sie dort an.

    Lösung anzeigen 
    cd ~/uebung

tail -n 1 notes/commands.txt                # letzte Zeile: grep

    Was jeder Befehl macht

    BefehlWirkung
    printf 'grep\n'Gibt das Wort grep mit einem Zeilenumbruch aus.
    >> dateiHängt die Ausgabe ans Ende der Datei an. Der vorhandene Inhalt bleibt erhalten. Gibt es die Datei nicht, wird sie angelegt.
    > dateiZum Vergleich: Überschreibt die Datei, der alte Inhalt ist weg.
    wc -l dateiZählt die Zeilen, hier jetzt 4.
    tail -n 1 dateiZeigt die letzte Zeile, also die gerade angehängte.

    Warum macht man es so?

    Anhängen statt neu schreiben: Mit >> ergänzen Sie eine Datei, ohne sie zu kennen oder neu aufzubauen. Typisch sind Logdateien, Notizen oder Konfigurationen, zu denen eine Zeile dazukommt.

    Mit Zeilenumbruch: printf 'grep\n' erzeugt eine vollständige Zeile. Ohne \n würde der nächste Anhängevorgang direkt hinter grep weiterschreiben.

    Vorher wichtig: Hat die vorhandene Datei am Ende keinen Zeilenumbruch, landet der neue Text an der letzten Zeile (aus mkdir wird mkdirgrep). Bei einer mit printf '…\n' erzeugten Datei ist das kein Problem.

    Kontrolle: cat zeigt den Inhalt, wc -l die Zeilenzahl. Erwartet sind 4.

    Typische Fehler

    FehlerFolge
    > statt >>Die Datei wird überschrieben und enthält danach nur noch grep (1 Zeile). Die alten drei Zeilen sind verloren.
    \n vergessenDie Zeile hat kein Ende. Die nächste Anhängeaktion klebt an grep.
    Altes Ende ohne ZeilenumbruchEs entsteht mkdirgrep statt zwei Zeilen. Vorher mit cat -A prüfen.
    Befehl zweimal ausgeführtDie Zeile steht doppelt, die Datei hat 5 Zeilen. >> prüft nicht, ob der Text schon da ist.
    Falscher PfadEs wird still eine neue Datei an anderer Stelle angelegt, wenn der Ordner existiert. Mit pwd und ls notes prüfen.
