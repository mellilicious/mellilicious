    Händeschütteln in Sillyville

    50 Bürger schütteln sich gegenseitig genau einmal die Hand. Schreibe Pseudocode und eine Methode handshakes(int people).

    Lösung mit Erklärung
    public class Handshakes {
    public static int handshakes(int people) {
        return people * (people - 1) / 2;
    }

    public static void main(String[] args) {
        System.out.println(handshakes(50));   // 1225
    }
}

    Warum so?

    • Pseudocode: INPUT people → STORE people * (people - 1) / 2 in handshakes → OUTPUT handshakes.
    • Zerlegen: Jede der n Personen schüttelt n−1 andere Hände. Muster: Dabei wird jedes Paar doppelt gezählt (A–B und B–A), also durch 2 teilen.
    • Abstraktion: Die Formel gilt für beliebiges n, nicht nur für 50. Genau das ist der Gauß-Trick aus der Vorlesung (1+2+…+49).
    • Erst multiplizieren, dann teilen: n*(n-1) ist immer gerade, die Ganzzahldivision /2 verliert also nichts.

    Typische Fehler: people * (people - 1) / 2 darf man nicht zu people / 2 * (people - 1) umstellen: bei ungeradem people rundet people / 2 ab und das Ergebnis stimmt nicht.

    Notenbewertung

    Name und Punkte (0–40) einlesen. Gerade oder ungerade? Prozentsatz berechnen. ≥ 90 „Excellent“, ≥ 75 „Good job“, ≥ 60 „Passed“, sonst „Needs improvement“.

    Lösung mit Erklärung
    import java.util.Scanner;

public class Grade {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        System.out.println("Welcome!");
        System.out.println("Enter your name:");
        String name = scanner.next();
        System.out.println("Enter your exam points (0-40):");
        int points = scanner.nextInt();

        if (points % 2 == 0) {
            System.out.println(points + " is even");
        } else {
            System.out.println(points + " is odd");
        }

        double percentage = points / 40.0 * 100;
        System.out.println(name + ", you achieved " + percentage + "%");

        if (percentage >= 90) {
            System.out.println("Excellent");
        } else if (percentage >= 75) {
            System.out.println("Good job");
        } else if (percentage >= 60) {
            System.out.println("Passed");
        } else {
            System.out.println("Needs improvement");
        }
    }
}

    Warum so?

    • points % 2 == 0 ist der Standardtest für „gerade“: Rest 0 bei Division durch 2.
    • 40.0 statt 40: Mit points / 40 wäre es Ganzzahldivision und das Ergebnis meistens 0.
    • Die else if-Kette läuft von der strengsten Bedingung zur schwächsten. Sobald ein Zweig passt, werden die anderen übersprungen. Deshalb muss man nicht „≥ 75 und < 90“ schreiben.
    • scanner.next() liest ein Wort (bis zum Leerzeichen), nextInt() eine ganze Zahl.

    Typische Fehler: Reihenfolge umdrehen (>= 60 zuerst) ergibt für 95 % fälschlich „Passed“. Wer nach nextInt() mit nextLine() weiterliest, bekommt oft nur den Rest der alten Zeile (leerer String).

    Menü mit switch und do-while

    Auswahl 1 = Sales, 2 = Stock, 3 = Admin, 0 = Ende. Bei ungültiger Eingabe „invalid selection“, am Ende „goodbye“.

    Lösung mit Erklärung
    import java.util.Scanner;

public class Menu {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        int selection;
        do {
            System.out.println("1 - sales");
            System.out.println("2 - stock");
            System.out.println("3 - admin");
            System.out.println("Select (0 to exit):");
            selection = scanner.nextInt();

            switch (selection) {
                case 1:
                    System.out.println("sales things");
                    break;
                case 2:
                    System.out.println("stock things");
                    break;
                case 3:
                    System.out.println("admin things");
                    break;
                case 0:
                    break;
                default:
                    System.out.println("invalid selection");
            }
        } while (selection != 0);
        System.out.println("goodbye");
    }
}

    Warum so?

    • do-while, weil das Menü mindestens einmal erscheinen muss, bevor man prüfen kann, ob der Benutzer beenden will.
    • selection wird vor der Schleife deklariert, damit die Bedingung nach dem Block sie noch sieht (Block-Scope).
    • switch passt hier gut: Es gibt feste Einzelwerte (1, 2, 3, 0). Bei Bereichen wie „≥ 75“ nimmt man if.
    • case 0: break; fängt die Ende-Eingabe ab, damit sie nicht in default landet.

    Typische Fehler: Ohne break am Ende jedes case fällt die Ausführung in den nächsten Zweig durch.

    Countdown

    Startzahl einlesen und bis 0 herunterzählen. Beispiel: 5 → 5 4 3 2 1 0.

    Lösung mit Erklärung
    import java.util.Scanner;

public class Countdown {
    public static void main(String[] args) {
        Scanner scanner = new Scanner(System.in);
        int n = scanner.nextInt();
        while (n >= 0) {
            System.out.print(n + " ");
            n--;
        }
    }
}

    Warum so?

    • Der Zähler (n) wird bei jedem Durchlauf verändert (n--). Sonst wäre die Schleife endlos.
    • Die Bedingung n >= 0 (nicht > 0) gibt die 0 noch mit aus.
    • print statt println, damit alle Zahlen in einer Zeile stehen.

    Typische Fehler: Wer n-- vergisst, hat eine Endlosschleife (Abbruch mit Strg-C).

        int result = 1;
        for (int i = 2; i <= n; i++) {
            result = result * i;
        }
        System.out.println(n + "! = " + result);
    }
}

    Warum so?

    • Das Ergebnis startet bei 1 (neutrales Element der Multiplikation). Mit 0 wäre alles 0.
    • Die Zählschleife for passt, weil die Anzahl der Wiederholungen bekannt ist (2 bis n).
    • Für n = 0 und n = 1 läuft die Schleife nicht und das Ergebnis bleibt 1. Das ist mathematisch richtig (0! = 1).

    Typische Fehler: int läuft bei 13! über (12! = 479001600 passt noch). Für größere n bräuchte man long oder BigInteger.

    Passwort mit drei Versuchen

    Höchstens 3 Versuche. Richtig: „Access granted“, sonst nach 3 Fehlversuchen „Access denied“.

public class PasswordRetry {

        Scanner scanner = new Scanner(System.in);
        final String PASSWORD = "secret";

        } else {
            System.out.println("Access denied");

}

    • Das Passwort als final-Konstante: Der Wert ändert sich nie.

    A3 · Array erweitern (5 Punkte)

    Methode extendArray(int[] arrayA, int[] arrayB): führt beide Arrays in einem neuen Array zusammen. Ist A länger als B, kommen zuerst die Elemente von B, dann die von A. Ist A kürzer als B, zuerst A, dann B. Sind beide gleich lang, wird abwechselnd befüllt, beginnend mit B.

    Lösung mit Erklärung
    import java.util.Arrays;

public class MidA3 {
    public static int[] extendArray(int[] arrayA, int[] arrayB) {
        int[] result = new int[arrayA.length + arrayB.length];
        int pos = 0;

        if (arrayA.length == arrayB.length) {
            for (int i = 0; i < arrayA.length; i++) {
                result[pos] = arrayB[i];
                pos++;
                result[pos] = arrayA[i];
                pos++;
            }
        } else if (arrayA.length < arrayB.length) {
            for (int i = 0; i < arrayA.length; i++) {
                result[pos] = arrayA[i];
                pos++;
            }
            for (int i = 0; i < arrayB.length; i++) {
                result[pos] = arrayB[i];
                pos++;
            }
        } else {
            for (int i = 0; i < arrayB.length; i++) {
                result[pos] = arrayB[i];
                pos++;
            }
            for (int i = 0; i < arrayA.length; i++) {
                result[pos] = arrayA[i];
                pos++;
            }
        }
        return result;
    }

    public static void main(String[] args) {
        System.out.println(Arrays.toString(extendArray(new int[]{1, 4, 5, 6}, new int[]{6, 7, 1, 3})));
        System.out.println(Arrays.toString(extendArray(new int[]{3, 4, 5, 6}, new int[]{1, 5})));
    }
}

    Warum so?

    • Die Größe des Ergebnisses steht von Anfang an fest: arrayA.length + arrayB.length. Deshalb kann man das Array gleich in voller Größe anlegen.
    • pos ist die nächste freie Stelle im Ergebnis und wird nach jedem Schreiben um 1 erhöht. Das ist einfacher als Indizes für drei Arrays gleichzeitig zu rechnen.
    • Drei Fälle, wie in der Angabe: gleich lang (abwechselnd, B zuerst), A kürzer (A dann B), A länger (B dann A). Der Fall „kürzeres zuerst“ ist in beiden Richtungen gleich, nur die Rollen tauschen.
    • Prüfe mit den Beispielen: A = {1,4,5,6}, B = {6,7,1,3} ergibt {6,1,7,4,1,5,3,6}. A = {3,4,5,6}, B = {1,5} ergibt {1,5,3,4,5,6}.
    • Arrays.toString(...) (Import java.util.Arrays) gibt ein Array lesbar aus. Ohne das druckt println(array) nur eine Adresse wie [I@1b6d3586.

    Typische Fehler: Den Fall „gleich lang“ zuerst prüfen. Er würde sonst im else landen und nicht abwechselnd befüllen. result[pos++] = ... ist eine übliche Kurzform, aber pos++ getrennt ist für Anfänger leichter zu lesen.

    B1 · Check Floats (5 Punkte)

    Methode compareDoubles(): liest zwei double-Werte ein und gibt true zurück, wenn sie bis zur dritten Nachkommastelle gleich sind, sonst false. Tipp: Math.abs der Differenz mit einem Grenzwert vergleichen.

    Lösung mit Erklärung
    import java.util.Scanner;

public class MidB1 {
    public static boolean compareDoubles() {
        Scanner scanner = new Scanner(System.in);
        System.out.println("Number1:");
        double number1 = scanner.nextDouble();
        System.out.println("Number2:");
        double number2 = scanner.nextDouble();

        return Math.abs(number1 - number2) < 0.001;
    }

    public static void main(String[] args) {
        System.out.println(compareDoubles());
    }
}

    Warum so?

    • Kommazahlen werden im Computer binär gespeichert und sind oft nur angenähert. Darum vergleicht man sie nicht mit ==, sondern prüft, ob der Abstand klein genug ist.
    • „Bis zur dritten Nachkommastelle gleich“ heißt: Der Abstand ist kleiner als 0,001. Beispiel 22,2227777 und 22,2229999: Abstand 0,0002222, also true.
    • Beispiel 1,1 und 1,1234: Abstand 0,0234 ist größer als 0,001, also false.
    • Math.abs macht den Abstand positiv, damit die Reihenfolge der Zahlen egal ist.
    • Der Ausdruck Math.abs(...) < 0.001 ist schon ein boolean und wird direkt zurückgegeben.
    • scanner.nextDouble() erwartet das Dezimalzeichen deiner Systemsprache. In der Angabe steht ein Komma (3,1234567), das passt zur deutschen Einstellung. In einer englischen Umgebung bräuchte man einen Punkt.

    Typische Fehler: Grenzfälle wie 1,0000 und 1,0010 (Abstand genau 0,001) liegen wegen Rundung nicht eindeutig. Die Angabe testet das nicht.

        String[] words = {"Those", "who", "do", "not", "remember", "the", "past",
                          "are", "condemned", "to", "repeat", "it"};
        System.out.println(countWordsStartWith(words, "th"));   // 1
    }
}

    Warum so?

    • Muster „Zähler“: count startet bei 0, geht jedes Element durch und wird bei jedem Treffer um 1 erhöht.
    • startsWith ist eine fertige String-Methode (laut Angabe erlaubt). Sie unterscheidet Groß- und Kleinschreibung: "Those" beginnt nicht mit "th", nur "the" trifft. Daher 1.
    • Der Rückgabewert kommt erst nach der Schleife, sonst würde die Methode nach dem ersten Element enden.

    Typische Fehler: equals ist hier falsch: Es würde nur komplette Wörter vergleichen. Ein null-Element im Array würde zu einer NullPointerException führen. Die Angabe schließt das aus.

    Midterm C Maximum und Minimum im Array, Array per Eingabe befüllen

    Code schreiben

    C1 · Array – Maximum und Minimum (5 Punkte)

    Methode getMaxAndMin(int[] numbers): gibt [max, min] zurück. Sind beide gleich, nur einen Wert [x]. Ist das Array leer, null.

    Lösung mit Erklärung
    import java.util.Arrays;

public class MidC1 {
    public static int[] getMaxAndMin(int[] numbers) {
        if (numbers.length == 0) {
            return null;
        }

        int max = numbers[0];
        int min = numbers[0];
        for (int i = 1; i < numbers.length; i++) {
            if (numbers[i] > max) {
                max = numbers[i];
            }
            if (numbers[i] < min) {
                min = numbers[i];
            }
        }

        if (max == min) {
            return new int[] {max};
        }
        return new int[] {max, min};
    }

    public static void main(String[] args) {
        System.out.println(Arrays.toString(getMaxAndMin(new int[]{1, 3, 6, -2, 0})));   // [6, -2]
        System.out.println(Arrays.toString(getMaxAndMin(new int[]{1, 1, 1, 1})));       // [1]
        System.out.println(Arrays.toString(getMaxAndMin(new int[]{})));                 // null
    }
}

    Warum so?

    • Sonderfall zuerst: Bei leerem Array gibt es kein numbers[0], der Zugriff würde abstürzen. Deshalb vorher null zurückgeben.
    • Max und Min starten mit dem ersten Element, nicht mit 0. Sonst wäre bei lauter negativen Zahlen das Maximum fälschlich 0.
    • Die Schleife beginnt bei Index 1, weil Index 0 schon als Startwert dient. Dasselbe Muster wie max3 aus Skript 04, nur für beliebig viele Werte.
    • Max und Min werden in einem Durchlauf mit zwei getrennten if geprüft. Ein Element kann nie beides gleichzeitig verbessern, aber so ist es am einfachsten zu lesen.
    • new int[] {max, min} legt ein Array direkt mit Werten an. Die Länge des Rückgabe-Arrays hängt vom Ergebnis ab (1 oder 2).

    Typische Fehler: Mit Arrays.sort ginge es auch (erstes und letztes Element), die Angabe will aber das Durchsuchen üben.

    C2 · Array befüllen (5 Punkte)

    Methode createArray(int length): legt ein int-Array dieser Länge an und liest so lange Zahlen ein, bis es voll ist. Wird 0 eingegeben, werden alle restlichen Stellen mit −1 befüllt. Ausgabe vor jeder Eingabe: Enter a number (n left):. Beispiel Länge 6 mit Eingaben 4, 8, 0 ergibt {4, 8, -1, -1, -1, -1}.

    Lösung mit Erklärung
    import java.util.Arrays;
import java.util.Scanner;

public class MidC2 {
    public static int[] createArray(int length) {
        Scanner scanner = new Scanner(System.in);
        int[] result = new int[length];

        for (int i = 0; i < length; i++) {
            System.out.println("Enter a number (" + (length - i) + " left):");
            int value = scanner.nextInt();

            if (value == 0) {
                for (int j = i; j < length; j++) {
                    result[j] = -1;
                }
                break;
            }
            result[i] = value;
        }
        return result;
    }

    public static void main(String[] args) {
        System.out.println(Arrays.toString(createArray(6)));
    }
}

    Warum so?

    • Das Array wird in voller Länge angelegt. Die Schleife läuft von 0 bis length - 1, jeder Durchlauf füllt eine Stelle.
    • Die Anzahl der noch offenen Eingaben ist length - i. Bei i = 0 also 6, dann 5 und so weiter, genau wie im Konsolenbeispiel.
    • Bei Eingabe 0 füllt eine zweite Schleife ab der aktuellen Stelle i alles mit −1 auf, auch die Stelle, an der die 0 eingegeben wurde. Danach beendet break die äußere Schleife.
    • Ohne break würde die Schleife weiter nach Zahlen fragen und die −1 überschreiben.
    • Das Array wird nach der Schleife zurückgegeben, egal ob es voll eingegeben oder mit −1 aufgefüllt wurde.

    Typische Fehler: Die 0 selbst darf nie in das Array gespeichert werden. Darum steht result[i] = value; erst nach dem if und wird bei 0 nicht erreicht.

    Midterm D Gemüsewaage mit String-Array, Reihenfolge von drei Zahlen

    Code schreiben

    D1 · Gemüsewaage Supermarkt (5 Punkte)

    Methode veggieScale(int maxItems): gibt zuerst Verwaltbare Positionen: <maxItems> aus und legt ein String-Array dieser Größe an. Danach wiederholt: Position (P:, 1-basiert) lesen, bei 0 Ende. Außerhalb 1 bis maxItems: „Ungueltige Position eingegeben“. Ist die Stelle belegt: „Speicherstelle bereits belegt“. Sonst Namen (N:) lesen und speichern. Rückgabe ist das Array.

    Lösung mit Erklärung
    import java.util.Arrays;
import java.util.Scanner;

public class MidD1 {
    public static String[] veggieScale(int maxItems) {
        Scanner input = new Scanner(System.in);
        System.out.println("Verwaltbare Positionen: " + maxItems);
        String[] items = new String[maxItems];

        while (true) {
            System.out.print("P: ");
            int pos = input.nextInt();
            input.nextLine();                 // Zeilenumbruch nach der Zahl verwerfen

            if (pos == 0) {
                break;
            }

            if (pos < 1 || pos > maxItems) {
                System.out.println("Ungueltige Position eingegeben");
            } else if (items[pos - 1] != null) {
                System.out.println("Speicherstelle bereits belegt");
            } else {
                System.out.print("N: ");
                items[pos - 1] = input.nextLine();
            }
        }
        return items;
    }

    public static void main(String[] args) {
        System.out.println(Arrays.toString(veggieScale(10)));
    }
}

    Warum so?

    • Endlosschleife while (true) mit break bei 0: Wir wissen vorher nicht, wie viele Eingaben kommen.
    • Position und Index: Der Benutzer zählt ab 1, das Array ab 0. Daher items[pos - 1]. Gültig ist 1 <= pos <= maxItems, also ist ungültig, was < 1 oder > maxItems ist.
    • Reihenfolge der Prüfungen: Erst den Bereich prüfen, dann die Belegung. Bei einer Position wie 14 würde items[13] sonst eine ArrayIndexOutOfBoundsException auslösen.
    • Neue String-Arrays enthalten null. Eine Stelle ist also frei, solange items[pos - 1] == null ist. Genau das verlangt die Angabe.
    • nextInt() liest nur die Zahl, der Zeilenumbruch bleibt im Puffer. Ohne das zusätzliche nextLine() würde der Name als leerer String gelesen. Das ist der Hinweis aus der Angabe.
    • Annahme: Bei ungültiger oder belegter Position wird kein Name abgefragt (wie im Konsolenbeispiel). Der Name wird nur bei einer freien, gültigen Stelle gelesen.

    Typische Fehler: items[pos] statt items[pos - 1] verschiebt alles um eins und stürzt bei pos == maxItems ab. Strings in Arrays werden mit equals verglichen, aber für den null-Test ist == null richtig und nötig (auf null kann man equals nicht aufrufen).

    D2 · Ordered Number Input (5 Punkte)

    Methode ordered(): liest drei ganze Zahlen ein (Number1:, Number2:, Number3: jeweils mit println). Rückgabe: 1 bei aufsteigend, -1 bei absteigend, sonst 0.

    Lösung mit Erklärung
    import java.util.Scanner;

public class MidD2 {
    public static int ordered() {
        Scanner scanner = new Scanner(System.in);
        System.out.println("Number1:");
        int a = scanner.nextInt();
        System.out.println("Number2:");
        int b = scanner.nextInt();
        System.out.println("Number3:");
        int c = scanner.nextInt();

        if (a < b && b < c) {
            return 1;
        }
        if (a > b && b > c) {
            return -1;
        }
        return 0;
    }

    public static void main(String[] args) {
        System.out.println(ordered());
    }
}

    Warum so?

    • „Aufsteigend“ heißt a < b **und** b < c. Beide Vergleiche müssen gelten, deshalb &&.
    • Wer nur a < c prüft, liegt bei 3, 2, 5 falsch: Die Zahlen sind weder auf- noch absteigend.
    • Das Ergebnis 0 ist der „Rest“: Wenn weder auf- noch absteigend gilt, bleibt nur 0. Deshalb steht es ohne eigene Bedingung am Ende.
    • Annahme: Gleiche Werte (z. B. 2, 2, 5) zählen nicht als geordnet, die Vergleiche sind strikt. Die Angabe nennt dafür kein Beispiel.

    Typische Fehler: Ausgabeformat beachten: Number1: ohne Leerzeichen nach dem Doppelpunkt und mit println.

    E1 · Multiplikationstabelle (5 Punkte)

    Methode printMultiplicationTable(int number, int rows): gibt das Einmaleins von number für rows Reihen aus (2*0=0, 2*1=2, …) und liefert alle geraden Produkte als Array ohne leere Stellen. Ist eine Zahl kleiner als 1: „Invalid input“ ausgeben und null zurückgeben.

    Lösung mit Erklärung
    import java.util.Arrays;

public class MidE1 {
    public static int[] printMultiplicationTable(int number, int rows) {
        if (number < 1 || rows < 1) {
            System.out.println("Invalid input");
            return null;
        }

        int[] evenProducts = new int[0];
        for (int i = 0; i < rows; i++) {
            int product = number * i;
            System.out.println(number + "*" + i + "=" + product);

            if (product % 2 == 0) {
                int[] bigger = new int[evenProducts.length + 1];
                for (int j = 0; j < evenProducts.length; j++) {
                    bigger[j] = evenProducts[j];
                }
                bigger[evenProducts.length] = product;
                evenProducts = bigger;
            }
        }
        return evenProducts;
    }

    public static void main(String[] args) {
        System.out.println(Arrays.toString(printMultiplicationTable(3, 5)));
        System.out.println(Arrays.toString(printMultiplicationTable(6, 5)));
        System.out.println(Arrays.toString(printMultiplicationTable(0, 5)));
    }
}

    Warum so?

    • Ungültige Eingaben werden gleich am Anfang abgefangen (number < 1 || rows < 1). Danach muss der Rest nicht mehr darauf achten. Ein Array kann man nicht „leer“ zurückgeben, das wäre etwas anderes als null.
    • Die Reihen beginnen bei 0: 2*0=0, 2*1=2, … Deshalb läuft die Schleife von 0 bis rows - 1. Bei (6, 5) ist die letzte Zeile 6*4=24, wie in der Angabe.
    • „Gerade“ prüft man mit product % 2 == 0. Die 0 zählt als gerade und gehört ins Ergebnis, die Beispiele beginnen auch bei 0.
    • Ein Array kann nicht wachsen. Darum die Idee aus dem Hinweis: Start mit Länge 0, bei jedem geraden Produkt ein um 1 größeres Array anlegen, alte Werte kopieren, neuen Wert hinten anfügen, dann das neue Array als evenProducts verwenden.
    • Am Ende hat das Array genau so viele Stellen wie gerade Produkte, ohne leere (0er-)Plätze.
    • Beispiel (3, 5): Produkte 0, 3, 6, 9, 12. Gerade sind 0, 6, 12, also [0, 6, 12].

    Typische Fehler: Wer das Array vorab mit Länge rows anlegt, hat am Ende leere Stellen (Nullen), und die Angabe verbietet das ausdrücklich. Das Ausgabeformat der Zeilen ist in der Angabe nicht ganz einheitlich (2*0=0 und 6 * 4 = 24). Getestet wird der Rückgabewert.

    E2 · Lichterkette (5 Punkte)

    Methode createFairyLights(int length): liest Farben r, g oder b ein und füllt damit ein char-Array der Länge length. Bei ungültiger Eingabe „Invalid value“ ausgeben und erneut fragen. Ausgabe vor jeder Eingabe: Choose a light color (r,g,b):.

    Lösung mit Erklärung
    import java.util.Arrays;
import java.util.Scanner;

public class MidE2 {
    public static char[] createFairyLights(int length) {
        Scanner scanner = new Scanner(System.in);
        char[] lights = new char[length];
        int count = 0;

        while (count < length) {
            System.out.println("Choose a light color (r,g,b):");
            String input = scanner.nextLine();

            if (input.equals("r") || input.equals("g") || input.equals("b")) {
                lights[count] = input.charAt(0);
                count++;
            } else {
                System.out.println("Invalid value");
            }
        }
        return lights;
    }

    public static void main(String[] args) {
        System.out.println(Arrays.toString(createFairyLights(3)));
    }
}

    Warum so?

    • while (count < length) statt for: Ein ungültiger Wert darf **nicht** als Durchlauf zählen. count wird nur bei gültiger Eingabe erhöht, so wird die Kette erst bei length gültigen Farben fertig.
    • Die Eingabe kommt als String, geprüft wird mit equals. Alles andere (R, rr, x) ist damit ungültig. Das große R im Konsolenbeispiel wird deshalb abgelehnt.
    • input.charAt(0) wandelt den einstelligen String in das char um, das im Array gespeichert wird.
    • Ein char schreibt man mit einfachen Anführungszeichen ('r'), ein String mit doppelten ("r").
    • Die Angabe nennt „Invalid value“, das Konsolenbeispiel zeigt „Invalid input“. Der Text steht nur auf der Konsole, getestet wird das zurückgegebene Array. Hier ist der Wortlaut aus dem Aufgabentext verwendet.

    Typische Fehler: Mit einer for-Schleife und continue bei ungültiger Eingabe würde der Zähler trotzdem weiterlaufen, und die Kette bliebe unvollständig.
